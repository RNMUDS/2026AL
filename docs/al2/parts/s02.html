2つの探索の違い

前期の最後に学んだ幅優先探索に加えて、第2回では深さ優先探索をあつかいます。 2つの探索は、コードの見た目こそよく似ていますが、見つける道がまったく違います。 違いはたった1行、「メモのどこを読むか」だけです。

2つの探索の呼び名（略したアルファベット）

日本語略した呼び名英語（元の言葉）言葉の意味
幅優先探索BFS（ビー・エフ・エス） Breadth-First Searchbreadth = 幅、first = 優先（先に）、search = 探索
深さ優先探索DFS（ディー・エフ・エス） Depth-First Searchdepth = 深さ、first = 優先（先に）、search = 探索

本やWebの説明では略した呼び名がよく使われます。例題のコードでも、search("bfs") は幅優先探索、search("dfs") は深さ優先探索を表します。

迷路で分かれ道に来ると、進める方向が2つ以上見えることがあります。 体は1つなので、同時に両方へは進めません。そこで「あとで見に行く場所」をメモに書いておきます。 メモの上から順に読めば幅優先探索、いちばん最後に書いた行から読めば深さ優先探索になります。 人が迷路を歩くときは、たいてい深さ優先探索と同じで「行けるところまで進んで、行き止まりなら引き返す」やり方をしています。

キューとスタック

キュー（queue）は「先に入れたものを先に取り出す入れもの」です。 レジの行列と同じで、先に並んだ人から順に呼ばれます。Pythonでは deque の popleft() で先頭を取り出します。

スタック（stack）は「あとから入れたものを先に取り出す入れもの」です。 積み重ねた本と同じで、いちばん上に置いた本から取ります。Pythonでは pop() で末尾を取り出します。

では、実際の迷路でメモがどう変わるかを見てみます。下の図は、例題の迷路で2つの探索を動かしたときの最初の4手順です。 マスの場所は (行,列) で表します。行は上から、列は左から数え、どちらも 0 から数えます（スタートの左上が (0,0)）。 どちらの探索も、手順1ではスタート (0,0) を読み、となりの (1,0)（下）と (0,1)（右）をメモに書き足します。 ちがいが出るのは手順2からです。

幅優先探索は、メモの左端（いちばん古い行）を読むので、下の (1,0) と右の (0,1) を交互に読み、スタートのまわりを少しずつ広げていきます。 深さ優先探索は、メモの右端（いちばん新しい行）を読むので、いま書き足したばかりの右のマスへ進み続けます。 下の (1,0) はメモの左端に書かれたまま、行き止まりに当たるまで読まれません。 この1行のちがいが、調べる順番と、見つかる道のちがいになります。

幅優先探索が最短を保証する理由

幅優先探索はメモを古い順に読むため、1歩で行ける場所をすべて調べ終えるまで、2歩の場所には進みません。 同じように、2歩の場所をすべて調べ終えてから3歩へ進みます。 歩数が少ない場所から順に調べているので、ゴールに最初に届いたときの歩数が、必ずいちばん少ない歩数になります。

深さ優先探索は歩数の順に調べません。行き止まりに当たるまで一方向へ進み続けるため、 遠回りの道を先に見つけてしまうことがあります。深さ優先探索が見つけた道は、最短とはかぎりません。

用語説明
幅優先探索（BFS）BFS は Breadth-First Search の略。スタートから近いマスから順に、同じ歩数のマスをすべて調べてから次の歩数へ進む探し方。見つかる道は必ず最短の歩数になる。
深さ優先探索（DFS）DFS は Depth-First Search の略。行き止まりに当たるまで一方向へ進み、行き止まりなら、まだ調べていない道が残っているいちばん最近の分かれ道まで戻って別の道を試す探し方。見つかる道は最短とはかぎらない。
スタックあとから入れたものを先に取り出す入れもの。積み重ねた本と同じ。Pythonのリストでは append() で入れて pop() で取り出す。
キュー先に入れたものを先に取り出す入れもの。レジの行列と同じ。Pythonでは deque の append() と popleft() を使う。
到達可能性「ゴールへ行けるかどうか」だけを判定すること。最短の道は要らないので、深さ優先探索でも十分な場合が多い。
トレードオフ一方を良くすると他方が悪くなる関係。幅優先探索と深さ優先探索は「道の短さ」と「調べる手間」がトレードオフの関係にある。

maze = [
    "S.....#",
    ".####.#",
    ".#....#",
    ".#.##..",
    ".#..#.#",
    ".##.#.#",
    "......G",
]

rows = len(maze)
cols = len(maze[0])

for r in range(rows):
    for c in range(cols):
        if maze[r][c] == "S":
            start = (r, c)
        if maze[r][c] == "G":
            goal = (r, c)

stack = [start]
came_from = {start: None}
visited_order = []
memo_log = []

while len(stack) > 0:
    current = stack.pop()
    visited_order.append(current)
    if current == goal:
        break

    r, c = current
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        nr = r + dr
        nc = c + dc
        if nr < 0 or nr >= rows or nc < 0 or nc >= cols:
            continue
        if maze[nr][nc] == "#":
            continue
        if (nr, nc) in came_from:
            continue
        came_from[(nr, nc)] = current
        stack.append((nr, nc))
    memo_log.append((current, list(stack)))

path = []
node = goal
while node is not None:
    path.append(node)
    node = came_from[node]
path.reverse()

print("深さ優先探索が見つけた経路の歩数:", len(path) - 1, "歩")
print("調べたマスの数:", len(visited_order), "マス")

def _font(size, bold=False):

def _memo_at(log, goal, k):
    """k 手順目（1から）に読んだマスと、そのあとのメモ。ゴールを読んだ手順は記録がないので作る。"""
    if k - 1 < len(log):
        return log[k - 1]
    memo = [cell for cell in log[-1][1] if cell != goal] if log else []
    return goal, memo

def neighbors(r, c):
    """上・下・左・右のうち、迷路の中にあって壁ではない場所を返す"""
    result = []
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        nr = r + dr
        nc = c + dc
        if nr < 0 or nr >= rows or nc < 0 or nc >= cols:
            continue
        if maze[nr][nc] == "#":
            continue
        result.append((nr, nc))
    return result

def search(mode):
    """mode が "bfs" なら幅優先探索、"dfs" なら深さ優先探索で迷路を解く"""
    memo = deque([start])
    came_from = {start: None}
    visited_order = []
    memo_log = []

    while len(memo) > 0:
        if mode == "bfs":
            current = memo.popleft()
        else:
            current = memo.pop()
        visited_order.append(current)
        if current == goal:
            break
        for next_cell in neighbors(current[0], current[1]):
            if next_cell in came_from:
                continue
            came_from[next_cell] = current
            memo.append(next_cell)
        memo_log.append((current, list(memo)))

    path = []
    node = goal
    while node is not None:
        path.append(node)
        node = came_from[node]
    path.reverse()
    return path, visited_order, memo_log

dfs_path, dfs_order, dfs_log = search("dfs")

# 幅優先探索と深さ優先探索を、同じ迷路で走らせて比べる
# 2つの探索のちがいは「メモのどこを読むか」の1行だけ。
#   幅優先探索: メモのいちばん古い行を読む → popleft()
#   深さ優先探索: メモのいちばん新しい行を読む → pop()
# その1行のちがいで、調べる順番と見つかる道がどう変わるかを表示する。

# deque（デック）は、両端から出し入れできるリストのようなもの。
# 先頭（いちばん古い行）を popleft()、末尾（いちばん新しい行）を pop() で取り出せる
from collections import deque

# --- 迷路 ---
# S = スタート、G = ゴール、# = 壁、. = 通路
# 文字列のリスト。maze[行][列] で1マスの文字が取り出せる（行・列は 0 から数える）

# def は「名前をつけた手順のまとまり（関数）」を作る文。() の中の r, c は引数（関数に渡す値の受け取り口）。
# 作っただけでは動かず、neighbors(0, 0) のように呼んだときに中身が実行される
def neighbors(r, c):
    """上・下・左・右のうち、迷路の中にあって壁ではない場所を返す"""
    result = []
    # (-1, 0) は上、(1, 0) は下、(0, -1) は左、(0, 1) は右へ1マス動くことを表す。
    # for dr, dc in ... は、組 (-1, 0) を取り出して dr = -1、dc = 0 のように2つの変数に分けて入れる
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        nr = r + dr
        nc = c + dc
        # 迷路の外に出てしまう場所は飛ばす（continue は「この回を飛ばして次へ」）
        if nr < 0 or nr >= rows or nc < 0 or nc >= cols:
            continue
        if maze[nr][nc] == "#":     # 壁も飛ばす
            continue
        result.append((nr, nc))
    return result

            current = ____      # ← 穴2

            break
        # いまのマスのとなりを調べ、まだメモに書いていない場所だけ書き足す。
        # current は (行, 列) の組なので、current[0] が行、current[1] が列
        for next_cell in neighbors(current[0], current[1]):
            # すでに記録がある場所を書き足すと、同じマスを何度も調べてしまうので飛ばす

                continue
            came_from[next_cell] = current
            memo.append(next_cell)      # メモの最後（いちばん新しい行）に書き足す

        # memo はこのあとも書き換わり続けるので、コピーしないと「その時点の中身」が残らない
        memo_log.append((current, list(memo)))

    # --- ゴールからスタートへ、came_from を逆にたどって通り道を作る ---

    path.reverse()              # ゴール→スタートの順を、スタート→ゴールの順に直す
    # return で3つの値をまとめて返す。受け取る側も3つの変数で受け取る
    return path, visited_order, memo_log
