ふり返り第5回のダイクストラ法は ①②③ のくり返し

出発点から近い駅から順に、時間を「もう変わらない」と決めていきました。

① 選ぶ　← 今回はここを変える

まだ確定していない駅のうち、時間がいちばん小さい駅を選ぶ。
第5回は、全部の駅を1つずつ見て比べていた。

② 確定する

選んだ駅の時間を「もう変わらない」と決める。

③ 書き直す

となりの駅に、もっと短い行き方が見つかれば時間を書き直す。

第6回で変えるのは ① だけ

②と③の考え方はそのまま。だから答え（最短の時間）は第5回とまったく同じです。

変わるのは「いちばん小さいものの探し方」と、それによる速さだけ。

全部見て比べると、何が困るの？

駅が n 個あると、1回選ぶのに n 回見る。それを n 回くり返すので、合計 n × n 回見ることになります。

地図場所の数全部見て比べる回数感覚でいうと
第5回の路線図66 × 6 = 36回一瞬
小さな地図1010 × 10 = 100回一瞬
カーナビの道路地図10万10万 × 10万 = 100億回待っていられない

場所が増えると、「いちばん小さいものを探す」作業が一番の重荷になる。
→ ここを速くできれば、ダイクストラ法全体が速くなる。

この箱の名前

優先度付きキュー。Python では heapq（ヒープキュー）という道具で使えます。

「いちばん小さいもの」の探し方をくらべる

同じ数の中から、いちばん小さい 3 を見つけたい。

全部見る（第5回）

2473112 4593816 5232719

12個あれば 12回 見る。100万個なら 100万回。

heapq に任せる（第6回）

37912 16192427

いちばん小さい数はいつも先頭。先頭を見るだけ。
取り出したあとの並べ直しも、100万個で 20回程度。

100万回 → 20回。場所が多いほど、差は大きくなる。

なぜ先頭がいちばん小さいの？ ── 箱のきまりはたった1つ

heapq は、中身を木の形に並べて、「親は必ず子より小さいか同じ」というきまりを守っています。

リストとしての中身

[1, 3, 2, 8, 9, 5]
ぱっと見はバラバラ。でも木にすると、どの親も子より小さい。

だから

いちばん小さい数は、必ず木のてっぺん ＝ 0番目にある。
→ 箱[0] を見るだけで最小がわかる。

注意

箱に append() で直接入れると、きまりが崩れる。
入れるのは heappush、出すのは heappop だけ。

heapq の使い方は3つだけ

箱はふつうのリスト。最初に import heapq と書いてから使います。

書き方すること
heapq.heappush(箱, 値)箱に値を1つ入れる
heapq.heappop(箱)いちばん小さい値を取り出す（箱からは消える）
箱[0]取り出さずに、いちばん小さい値を見るだけ

組（タプル）も入れられる

(16, "品川") のように数を先に書いた組を入れると、1番目の数の小さい順に出てくる。

(16, "品川") と (30, "品川") → 16 のほうが先。
数が同じなら、2番目の名前でくらべる（カタカナならだいたいアイウエオ順）。

ダイクストラ法では (その駅までの時間, 駅名) を箱に入れる → 時間の短い駅から順に出てくる

heapq 版のダイクストラ法 ── 変わるのはここ

箱の名前は queue（キュー：待ち行列）。中に (時間, 駅名) の組を入れます。

第5回（全部見る）第6回（heapq）
① 選ぶfor で全部の駅を見て、いちばん小さい駅を探すheapq.heappop(queue) の1行で取り出す
③ 書き直す距離表を書き直すだけ書き直したら、(新しい時間, 駅名) を heappush で箱にも入れる
確定済みの駅が出てきたら（起きない）読み飛ばす（次のスライド）
終わるとき全部の駅が確定したとき箱（queue）が空っぽになったとき

②「確定する」の考え方は、第5回とまったく同じ。

新宿から、箱を使って解いてみる（heappop 7回）

箱から出てくるのは、いつも時間がいちばん小さい組。出てきた駅を確定し、となりの駅の組を箱に入れます。

回取り出す前の箱の中身取り出した組したこと
1(0, 新宿)(0, 新宿)新宿を0分で確定。渋谷7・池袋9・品川30 を入れる
2(7, 渋谷) (9, 池袋) (30, 品川)(7, 渋谷)渋谷を7分で確定。品川 30→16 に書き直して (16, 品川) を入れる

確定の順番と時間（0・7・9・16・21・27分）は、第5回の手計算とまったく同じ。

気をつけるところ ── 古い札は無視する

heapq 版では、同じ駅の札が箱に2枚入ることがあります。

品川に何が起きた？

1回目：新宿から直通で (30, 品川) を入れる。
2回目：渋谷経由のほうが速いとわかり、(16, 品川) をもう1枚入れる。

古い30分の札は消さずに残しておく（箱の途中の札を消すのは手間がかかるから）。

でも大丈夫

小さい順に出てくるので、16分の札が先に出て品川が確定する。
最後に出てくる30分の札は「もう決まった駅の古い札」なので無視（読み飛ばし）すればOK。

コードでは

minutes, current = heapq.heappop(queue)
if current in settled:
    continue　← 確定済みなら次へ

読み飛ばさないと、確定済みの駅をもう一度「確定」と表示して、むだな作業が増えます。

読み飛ばしは何回起きる？

時間の書き直しが起きた回数だけ起きる。
（新宿の例では書き直しが1回 → 読み飛ばしも1回）
