動的計画法（bitDP）

第8回の全探索（すべての順番を試す方法）は必ず最短を出しますが、10か所をこえると待てなくなり、15か所では数時間かかる見積もりでした。 第9回の貪欲法（いちばん近い場所へ進むことをくり返す方法）は一瞬で終わりますが、最短とはかぎりませんでした（ナガシマスパーランドのひな形では 7.6% おそい回り方でした）。 第10回で学ぶ動的計画法（どうてきけいかくほう）は、 必ず最短を出しながら、全探索よりずっと速い方法です。 「貪欲法の回り方は、本当の最短より何分おそいのか」を、全探索では確かめられなかった15か所でも確かめられるようになります。

上の図は、演習のひな形の6か所を、2つの方法で回ったものです。 左の貪欲法は、いちばん近い場所を5回えらぶだけで回り方が決まります。 右の bitDP は、先に表を埋めてから回り方を決めるので手間はかかりますが、出てくるのは必ず最短の回り方です。 貪欲法は、大観覧車オーロラから近いアクロバットを先にえらんだため、最後に白鯨からメインゲートまでの長い道が残りました。

ナガシマスパーランドで、友だちと別べつに回って、とちゅうで合流した場面を思い浮かべてください。 2人とも「スチールドラゴン2000・嵐・白鯨の3つに乗り終えて、いま白鯨の前にいる」とします。 あなたは「スチールドラゴン → 嵐 → 白鯨」の順で30分、友だちは「嵐 → スチールドラゴン → 白鯨」の順で25分かかりました。 ここから先、残りの乗り物をどう回るのがいちばん早いかは、2人ともまったく同じです。 乗り終えたものが同じで、いまいる場所も同じだからです。どの順番で乗ってきたかは、この先には関係ありません。 だとすれば、25分のほうだけをメモしておけばよく、30分かかった順番の続きは、もう考えなくてすみます。 動的計画法は、この「同じ状況に着いたら、いちばん良い記録だけをメモして、続きの計算を使い回す」という考え方です。

全探索のむだ

全探索は「0 → 1 → 2 → 3 → …」と「0 → 2 → 1 → 3 → …」を、まったく別のものとして最後まで調べます。 しかし2つの道は、4つ目の都市に着いた時点で状況がまったく同じです。 どちらも「0・1・2・3 を回り終えて、いま 3 にいる」からです。

残っている都市も同じ、いる場所も同じなので、ここから先のいちばん短い進み方も同じになります。 ちがうのは「ここまでにかかった距離」だけです。 短いほうの距離だけを覚えておけばじゅうぶんで、長いほうの道の続きは、もう調べる必要がありません。 全探索は、この「続き」を道Aでも道Bでも1から計算し直していました。

覚えておく2つのこと ── 「状態」

覚えること意味コードでの名前
回った都市の集合どの都市をすでに回ったか（順番は関係ない）visited
いまいる都市最後に着いた都市here

この2つの組を状態（じょうたい）と呼びます。「いま、どういう状況か」を表す情報、という意味です。 「集合」（しゅうごう）は、順番を気にしない「ものの集まり」のことです。 状態が同じなら、そこまでのいちばん短い距離だけを表に書いておきます。 一度計算した答えをメモしておいて使い回すことをメモ化と呼び、動的計画法の中心になる考え方です。 動的計画法は、英語の Dynamic Programming の頭文字から DP（ディーピー）とも呼ばれます。

集合を、数1つで表す ── ビット

「回った都市の集合」を、Python のリストではなく1つの整数で表します。 使うのは2進数（にしんすう: 0 と 1 だけで書く数の表し方。ふだん使う10進数の 5 は、2進数では 101 と書く）です。 2進数の1けたをビットと呼びます。 都市が5個なら5けたの2進数を使い、i番の都市を回っていれば、右から数えて i番目のけた（右はしが0番）を 1 にします。 遊園地のスタンプカードで、行った場所のマスにスタンプを押すのと同じです。

書き方読み方意味
1 << i左シフトi番の都市だけを表す数（1 を左へ i けたずらす。1 << 3 は 2進数の 01000 = 8）
visited | (1 << i)または（or）集合に i番の都市を足す（スタンプを押す）
visited & (1 << i)かつ（and）集合に i番の都市が入っているか調べる（0 以外なら入っている）

整数1つで集合を表せるので、best[visited][here] のように リストの番号としてそのまま使えます。 ビットを使った動的計画法なので、bitDP（ビットディーピー）と呼ばれます。 3つの記号の使い方は、例題1と演習1で練習します。

bitDP も万能ではありません。場所が1つ増えるたびに、表の大きさは2倍より少し多く増えます。 25か所では表が約8億マスになり、時間より先に、パソコンのメモリ（計算のとちゅうの値を覚えておく場所）が足りなくなります。 それでも、場所が1つ増えるたびに調べる量が何倍にもなる全探索（10か所から11か所で10倍、19か所から20か所で19倍）に比べれば、ずっとゆるやかです。 「必ず最短がほしくて、20か所くらいまで」なら bitDP、「もっと多い」なら貪欲法、という使い分けになります。

例題 1

集合を数1つで表し、ナガシマスパーランドのスタンプカードを作る

bitDP を書く前に、集合を数1つで表す練習をします。 覚える記号は <<（ずらす）、|（足す）、&（入っているか調べる）の3つだけです。 演習1では、同じしくみでナガシマスパーランドの「行った場所のスタンプカード」を作ります。

3つの記号の使い方

① 1 << i ── i番の都市だけを表す数を作る

何をしているか: << は「左へずらす」記号です。1 << i は、2進数の 1 を左へ i けたずらした数になります。 1 << 0 は 00001（= 1）、1 << 1 は 00010（= 2）、1 << 2 は 00100（= 4）、1 << 3 は 01000（= 8）です。 1けたずらすたびに、数は2倍になります。

なぜそう書くか: 「i番のけただけが 1 の数」がほしいからです。この数を、下の | や & と組み合わせて使います。

② visited | (1 << i) ── 集合に i番の都市を足す

何をしているか: |（たて棒。キーボードでは Shift を押しながら ¥ のキー）は、2つの数を2進数で上下に並べ、 けたごとに「どちらかが 1 なら 1」にします。もともと 1 だったけたはそのままで、i番のけたが新しく 1 になります。

考え方 ── | で図書館（2番）を足す
  01011    visited（学校・郵便局・カフェ）
| 00100    1 << 2（図書館だけ）
-------
  01111    どちらかが 1 のけたは 1 → 図書館が足された

なぜ + ではだめか: もう入っている都市を + で足すと、くり上がりが起きて別の集合になってしまいます（00100 + 00100 = 01000）。 | なら、もう入っている都市を足しても何も変わりません。

③ visited & (1 << i) ── i番の都市が入っているか調べる

何をしているか: &（アンド）は、けたごとに「両方が 1 のときだけ 1」にします。 1 << i は i番のけたしか 1 ではないので、答えは「i番のけたが 1 なら 0 以外、0 なら 0」になります。

考え方 ── & で、入っているかを調べる
  01011    visited（学校・郵便局・カフェ）          01011    visited
& 00100    1 << 2（図書館だけ）                  & 01000    1 << 3（カフェだけ）
-------                                          -------
  00000    両方が 1 のけたがない → 0             01000    両方が 1 のけたがある → 0 ではない
           → 図書館は入っていない                         → カフェは入っている

if visited & (1 << i): と書ける理由: Python の if は、数が 0 なら「いいえ」、0 以外なら「はい」として扱います。だから != 0 を書かなくても、「入っていれば」という意味になります。

①② 表を作り、はじめの状態を書く

何をしているか: best は、行が 1 << count 個（集合の数。5都市なら32行）、列が count 個（いまいる都市）の表です。 はじめは全部のマスに INF を入れておきます。 出発するときは「0番だけ回って（集合は 00001 = 1 << 0）、0番にいる」ので、そのマスだけ 0 にします。 prev（プレブ: previous = 前の、という意味）は同じ形の表で、「そのマスへ、どの都市から来たか」を覚えておきます。あとで回る順番をたどるために使います。

③④ 集合を小さい数から順に見て、たどり着ける状態だけを使う

何をしているか: 表のマスを上の行から順に見ていき、値が INF のまま（たどり着けない状態）なら continue（この回の残りを飛ばして次へ進む命令）で飛ばします。 たとえば「集合が 00011（学校と郵便局）なのに、いま図書館にいる」という状態はありえないので、INF のままです。

def make_table(places):
    """第8回と同じ距離の表を作る。table[i][j] = i番から j番までの直線距離（小数第1位まで）"""
    table = []
    for i in range(len(places)):
        row = []
        for j in range(len(places)):
            dx = places[i][1] - places[j][1]
            dy = places[i][2] - places[j][2]
            row.append(round(math.sqrt(dx ** 2 + dy ** 2), 1))
        table.append(row)
    return table


def bit_dp(table):
    """bitDP。0番を出発して全部の都市を回り、0番へ戻るいちばん短い順番・合計距離・表 best を返す"""
    count = len(table)                # 都市の数
    full = (1 << count) - 1           # 全部の都市を回った集合（5都市なら 11111 = 31）
    best = []                         # best[visited][here] = その状態までの、いちばん短い距離
    prev = []                         # prev[visited][here] = その状態へ、どの都市から来たか（あとで順番をたどるため）
    for visited in range(1 << count):             # 表を作る。行は 2のcount乗 個（集合の数）、列は count 個
        best.append([INF] * count)
        prev.append([None] * count)
    best[1 << 0][0] = 0               # はじめの状態: 0番だけ回って（00001）、0番にいる。距離は 0

    # 集合を表す数の、小さいほうから順に見る。都市を1つ足した集合は、いまより必ず大きい数になるので、
    # 小さい順に見れば、ある行を読むときには、その行の値はもう決まっている
    for visited in range(1 << count):
        for here in range(count):
            if best[visited][here] == INF:        # たどり着けない状態は飛ばす
                continue
            for next_city in range(count):        # ここから次に行く都市を、全部ためす
                if visited & (1 << next_city):    # もう回った都市へは行かない
                    continue
                new_visited = visited | (1 << next_city)          # next_city を足した集合
                new_length = best[visited][here] + table[here][next_city]
                if new_length < best[new_visited][next_city]:     # いま表にある値より短いときだけ、書きかえる
                    best[new_visited][next_city] = new_length
                    prev[new_visited][next_city] = here           # どこから来たかも覚えておく

    # 全部回った状態（full の行）のうち、0番へ戻る距離を足して、いちばん短くなるものをえらぶ
    answer = INF
    last = None                       # 最後に立ちよる都市
    for here in range(1, count):
        total = best[full][here] + table[here][0]
        if total < answer:
            answer = total
            last = here

    # prev を後ろから前へたどって、回る順番を作る
    route = []
    visited = full
    here = last
    while here is not None:           # 0番の prev は None なので、0番まで来たら終わる
        route.append(here)
        came_from = prev[visited][here]           # here へ来る前にいた都市
        visited = visited - (1 << here)           # here のけたを 0 にもどす（here を回る前の集合）
        here = came_from
    route.reverse()                   # 後ろからたどったので、前後を逆にする
    return route, round(answer, 1), best


def brute_force(table):
    """全探索（第8回と同じ）。0番を出発する順番をすべて試して、いちばん短い順番・合計距離・試した数を返す"""
    best_order = None
    best_length = None
    tried = 0
    for order in permutations(range(1, len(table))):
        total = 0
        here = 0
        for city in order:
            total = total + table[here][city]
            here = city
        total = total + table[here][0]
        tried = tried + 1
        if best_length is None or total < best_length:
            best_length = total
            best_order = order
    return [0] + list(best_order), round(best_length, 1), tried

def _fit(font, text, width):
    """text が width ピクセルに収まらなければ、後ろを「…」にして縮める。"""
    if font.size(text)[0] <= width:
        return text
    while text and font.size(text + "…")[0] > width:

    return text + "…"


def _loop(screen, fonts, last_step, draw, hint):

class _MapView:
    """地点の (x, y) を、窓の中の四角 (left, top, w, h) に収まるように置きかえる。"""

    def __init__(self, places, left, top, w, h):
        xs = [p[1] for p in places]
        ys = [p[2] for p in places]
        self.x0, self.y0 = min(xs), min(ys)
        self.scale = min((w - 80) / max(max(xs) - self.x0, 1), (h - 70) / max(max(ys) - self.y0, 1))
        self.left = left + 40 + ((w - 80) - (max(xs) - self.x0) * self.scale) / 2

    def pos(self, place):
        return (int(self.left + (place[1] - self.x0) * self.scale),

def bit_dp(table):
    """bitDP（例題2と同じ）。0番を出発して全部回り、0番へ戻るいちばん早い順番と合計の分を返す"""
    count = len(table)                # 場所の数
    full = (1 << count) - 1           # 全部の場所に行ったスタンプカード（1 が count 個ならぶ数）
    best = []                         # best[visited][here] = その状態までの、いちばん短い分
    prev = []                         # prev[visited][here] = その状態へ、どの場所から来たか
    for visited in range(1 << count):             # 表を作る。行は 2のcount乗 個（スタンプカードの種類）
        best.append([INF] * count)
        prev.append([None] * count)
    best[1 << 0][0] = 0               # はじめの状態: 0番だけ行って、0番にいる。0分

    # スタンプカードの数の、小さいほうから順に見る。スタンプを1つ押すと、数は必ず大きくなるので、
    # 小さい順に見れば、ある行を読むときには、その行の値はもう決まっている
    for visited in range(1 << count):
        for here in range(count):
            if best[visited][here] == INF:        # たどり着けない状態は飛ばす
                continue
            for next_place in range(count):       # ここから次に行く場所を、全部ためす
                if visited & (1 << next_place):   # もう行った場所へは行かない（演習1の & ）
                    continue
                new_visited = visited | (1 << next_place)         # スタンプを1つ押す（演習1の | ）
                new_total = best[visited][here] + table[here][next_place]
                if new_total < best[new_visited][next_place]:     # いま表にある値より早いときだけ、書きかえる
                    best[new_visited][next_place] = new_total
                    prev[new_visited][next_place] = here

    answer = INF                      # 全部行った行のうち、0番へ戻る分を足して、いちばん早いものをえらぶ
    last = None
    for here in range(1, count):
        total = best[full][here] + table[here][0]
        if total < answer:
            answer = total
            last = here

    route = []                        # prev を後ろから前へたどって、回る順番を作る
    visited = full
    here = last
    while here is not None:
        route.append(here)
        came_from = prev[visited][here]           # here へ来る前にいた場所
        visited = visited - (1 << here)
        here = came_from
    route.reverse()
    return route, round(answer, 1)


def greedy(table, start):
    """貪欲法（第9回と同じ）。いちばん近い場所へ進むことをくり返す。回る順番と合計の分を返す"""
    count = len(table)
    visited = [start]                 # こちらの visited は、行った場所の番号を行った順に入れるリスト
    total = 0
    here = start
    while len(visited) < count:
        nearest = None
        for j in range(count):
            if j in visited:
                continue
            if nearest is None or table[here][j] < table[here][nearest]:
                nearest = j
        total = total + table[here][nearest]
        visited.append(nearest)
        here = nearest
    total = total + table[here][start]
    return visited, round(total, 1)


def brute_force(table):
    """全探索（第8回と同じ）。いちばん早い順番・合計の分・試した順番の数を返す"""
    best_order = None
    best_total = None
    tried = 0
    for order in permutations(range(1, len(table))):
        total = 0
        here = 0
        for place in order:
            total = total + table[here][place]
            here = place
        total = total + table[here][0]
        tried = tried + 1
        if best_total is None or total < best_total:
            best_total = total
            best_order = order
    return [0] + list(best_order), round(best_total, 1), tried

def how_long(sec):
    """秒を、読みやすい単位（秒・分・時間・日・年）の文字にする。とても大きいときは「10の何乗 年」と書く"""
    years = sec / (365 * 24 * 3600)
    if years >= 1000000:
        return f"約10の{len(str(int(years))) - 1}乗 年"
    for size, unit in [(365 * 24 * 3600, "年"), (24 * 3600, "日"), (3600, "時間"), (60, "分")]:
        if sec >= size:
            return f"約{sec / size:,.1f}{unit}"
    if sec < 0.01:
        return "0.01秒より短い"
    return f"約{sec:.2f}秒"

def _fit(font, text, width):
    """text が width ピクセルに収まらなければ、後ろを「…」にして縮める。"""
    if font.size(text)[0] <= width:
        return text
    while text and font.size(text + "…")[0] > width:
        text = text[:-1]
    return text + "…"


def _loop(screen, fonts, last_step, draw, hint):
    """窓のくり返し処理。draw(k) が k 手順目の画面を描く。"""
    capture = os.environ.get("AL2_CAPTURE")      # 授業ページの画像を作るときだけ使う
    k = int(os.environ.get("AL2_STEP", last_step)) if capture else 0
    playing = False
    clock = pygame.time.Clock()
    last = pygame.time.get_ticks()
    while True:
        for event in pygame.event.get():
            if event.type == pygame.QUIT:
                pygame.quit()
                return
            if event.type == pygame.KEYDOWN:
                if event.key == pygame.K_ESCAPE:
                    pygame.quit()
                    return
                if event.key == pygame.K_SPACE:
                    playing = not playing
                if event.key == pygame.K_RIGHT and k < last_step:
                    k += 1
                    playing = False
                if event.key == pygame.K_r:
                    k, playing = 0, False
        if playing and pygame.time.get_ticks() - last >= STEP_MS:
            last = pygame.time.get_ticks()
            if k < last_step:
                k += 1
            else:
                playing = False
        screen.fill(BG)
        draw(k)
        h = fonts[2].render(hint, True, SUB)
        screen.blit(h, (30, screen.get_height() - 30))
        pygame.display.flip()
        if capture:
            pygame.image.save(screen, capture)
            pygame.quit()
            return
        clock.tick(30)


class _MapView:
    """地点の (x, y) を、窓の中の四角 (left, top, w, h) に収まるように置きかえる。"""

    def __init__(self, places, left, top, w, h):
        xs = [p[1] for p in places]
        ys = [p[2] for p in places]
        self.x0, self.y0 = min(xs), min(ys)
        self.scale = min((w - 80) / max(max(xs) - self.x0, 1), (h - 70) / max(max(ys) - self.y0, 1))
        self.left = left + 40 + ((w - 80) - (max(xs) - self.x0) * self.scale) / 2
        self.top = top + 40 + ((h - 70) - (max(ys) - self.y0) * self.scale) / 2
        self.rect = pygame.Rect(left, top, w, h)

    def pos(self, place):
        return (int(self.left + (place[1] - self.x0) * self.scale),
                int(self.top + (place[2] - self.y0) * self.scale))


def _draw_panel(screen, view):
