説明

1.0 まず全体像 ── カウンティングソートって何をするの？

これまでのソートは「2つを比べて大きいほうを後ろへ」という作業の繰り返しでした。カウンティングソート（分布数えソート）はまったく違う発想で、1つも比べません。代わりに「どの値が何個あるかを数える」だけで並べ替えます。手順はたったの3ステップです。

  1. ① マスを用意する：出てくる値の種類ぶんだけ「置き場所（マス）」を並べます。たとえば値が 0〜3 の4種類なら、0番・1番・2番・3番の4つのマス。
  2. ② 配って数える：データを1個ずつ「その値と同じ番号のマス」に入れていきます。大小はいっさい比べません。配り終えると、各マスには「その値が何個あったか」がたまっています。
  3. ③ 取り出す：マスを0番から順番に取り出して並べるだけ。番号の小さいマスから出すので、取り出した時点でもう整列済みです。
たとえ（郵便局の仕分け）： 大量のハガキを郵便番号順に並べる係員は、ハガキ同士を見比べたりしません。番号ごとの仕切り棚にポンポン放り込むだけ。全部入れ終えたら、棚を番号の小さい順に取り出す ── それだけでもう並んでいます。この「仕切り棚」がマスにあたります。

では実際の動きを、3つの例で順に見ていきましょう。(1) まず小さな例で仕組みを、(2) 次に件数の多い例で「データが増えても速い」ことを、(3) 最後に「マスが多すぎる」例で苦手な場面を確認します。

(1) 仕組みを見る ── 入力 [2, 0, 3, 1, 2] を並べ替える

上の入力のボールが 真ん中のマスへ落ちていくのが ①数える。値2が2個あるので、緑のボールは同じ「マス2」に重なります。配り終えたら、マスを 0番→1番→2番→3番の順に取り出して 下の出力へ並べる ── これが ②取り出す。一度も大小を比べないまま [0, 1, 2, 2, 3] が完成します。この「数える→並べる」を配列で実際にどう書くか（度数配列・累積度数）は 1.2 で説明します。

(2) データが多くても速い ── n = 1000 個・値の種類 k = 10 を自分で動かす

こんどは件数を1000個に増やします。それでもやることは同じで、1個ずつ「その値のマス」に入れて数えるだけ。今回は数えた結果を棒の高さで表すので、各マスの高さ＝その値が何個あったかになります。再生で自動、ステップで少しずつ進み、リセットで最初に戻ります。実際に動かして、マスがどんどん埋まっていく様子を見てください。

ポイントは、要素が1000個でもマスの数は10個のままだということ。やるのは「1個ずつマスに入れて数える」だけで（やはり比べていません）、数え終わったらマス0→マス9の順に取り出すと整列完了 ── 下に色分けの帯で結果が出ます。件数 n が10倍・100倍に増えても、手数はそれに比例して増えるだけ。これが O(n+k)、つまり「データ量に正比例（線形）」の速さです。

(3) 苦手な場面 ── 「マスが多すぎる」例（n = 1000・k = 1000、空マスが出る）

最後は、わざと苦手な条件を作ります。値の範囲を 0〜999 に広げると、マスは1000個必要。でもデータは1000個しかないので、同じ値はめったに重ならず、ほとんどのマスは0個か1個です。さらに1度も使われない「空マス」が大量に出ます。それでも手順は (1)(2) と同じ ── 動かして、グラフがどれだけスカスカになるか見てください。

処理済み 0 / 1000 ｜ 使ったマス 0 ｜ 空マス 1000

ここがポイント: グラフはスカスカで、すき間（＝空マス）だらけです。ところが空マスも、用意する（作る）・最後に順番に調べる、という手間からは逃れられません。つまり k が大きいほど +k の負担がそのまま増えます。k が n と同じくらい大きいと、この空マスの手間が効いてきて、カウンティングソートの「速さ」のうま味が薄れます。だからこの方法は 「値の範囲（k）が狭い整数」のときにこそ強い、と覚えておきましょう（くわしくは発展課題で確かめます）。

1.1 これまでのソートとの違い

読み方: counting sort = カウンティング・ソート（直訳すると「数えてソート」）。日本語では「分布数えソート」「度数分布法によるソート」とも呼ぶ。 関連語: frequency＝フリークエンシー（度数）、cumulative＝キュムレイティブ（累積）、stable sort＝ステイブル・ソート（安定ソート）。

これまで学んだ挿入ソートや、第9回で学んだバブルソート（隣り合う要素を比べて大きいほうを後ろへ送る方式）は、いずれも「この2枚のカードはどちらが大きい？」と要素同士を比較しながら順序を決めていました。じつは、こうした比較を繰り返すソートは、どんなに工夫しても最速で O(n log n) より速くできないことが数学的に証明されています（これを比較ベースのソートの下限と呼びます）。第9回では挿入ソート・二分挿入ソート・バブルソートを比べましたが、どれもこの O(n log n) の壁の中の話でした。

分布数えソート（Counting Sort）は比較を一切使いません。代わりに、各値が何回出現するかを数えることでソートします。

方式アプローチ計算量
比較ベース
（挿入ソート・バブルソート など / 第9回）		「AとBはどちらが大きい？」を繰り返す最速でも O(n log n)
分布数えソート「値0は何個？値1は何個？...」と数えて並べ直すO(n + k)

1.1+ 「比較ベースのソートの下限」って何？

「比較ベースのソートの下限」とは、ひとことで言うと
「2つを比べて並べるやり方では、どんなに頭をひねっても、これより速くはならない」という"速さの限界ライン"のことです。そのラインが O(n log n) です。

なぜ限界ができるのか（イメージ）

比較ソートは「AとB、どっちが大きい?」というはい / いいえ の質問を繰り返して並び順を当てていくゲームだと考えてください。

  • n 個の要素の並び方は全部で n!（n の階乗）通りあります（例: 3個なら 3×2×1 = 6通り）。
  • 1回の質問（比較）で、候補をせいぜい半分にしか絞れません（はい/いいえの2択だから）。
  • 「全部で n! 通り」を「半分ずつ」絞って1つに特定するには、最低でも log₂(n!) ≒ n log n 回の質問が必要になります。

つまり「比べて並べる」という方法をとる限り、n log n 回より少ない比較では絶対に並べ替えられない。これが「下限（＝最低でもこれだけかかるライン）」です。挿入ソートもバブルソートも、どんな新しい比較ソートを考えても、このラインは超えられません。

たとえ： 「Yes/No で答える質問」だけで相手の思い浮かべた数を当てるゲーム。1回の質問で選択肢は半分にしか減らないので、候補が多いほど質問回数は増えます。比較ソートはこの"質問ゲーム"そのもの。だから比較に頼る限り、回数（＝速さ）に超えられない壁ができるのです。

では矛盾しない？ 「O(n log n) より速くできない」のに分布数えソートが O(n+k) で速いのは、分布数えソートが"比べていない"からです。下限のルールは「比べて並べる人」だけに適用されるルール。分布数えソートは「値を数えて置くだけ」で別の土俵にいるので、このルールに縛られず壁を回避できます。
（徒競走の世界記録は自転車には関係ない、のと同じイメージ）

1.1++ 「O(n log n)」を具体的に

まず log n は「何回 半分にできるか」

例: 1000ページの辞書から1語を探す。真ん中を開けば前半/後半に半分に絞れる。これを繰り返すと 1000→500→250→…→1 は約10回。だから log₂1000 ≒ 10。n が100万に増えても約20回＝ log n は「桁数みたいなもの」で、ほんの少ししか増えません。

データ件数 nlog₂ n（1になるまで半分にする回数）
83
1,000約 10
100万約 20

なぜソートが n × log n になる？（n=8で実演）

賢いソート（マージソート）は「束を半分ずつに分けて → 各段で全部を整える」をします。右側の数字は「1かたまりに入っている個数」で、割るたびに半分になります。

[5,3,8,1,9,2,7,4]          ← 1かたまり 8個
[5,3,8,1] [9,2,7,4]        ← 半分に分割：1かたまり 4個（1段目）
[5,3][8,1] [9,2][7,4]      ← また半分：1かたまり 2個（2段目）
[5][3][8][1][9][2][7][4]   ← また半分：1かたまり 1個（3段目）

  1かたまりの個数：8 → 4 → 2 → 1（半分にした回数＝3回）
  この「半分にした回数 3」＝ 3段 ＝ log₂8

そのあと、整えながらくっつけ直すとき、各段で8個すべてを1回ずつ見ます（＝1段あたり n 手）。それが 3段（log n 段）ぶん。

8（n個）× 3（log n 段）= 24手 ≒ n × log n

数字で比べると（k は小さいとして）

データ件数 n比較ソート n log n分布数えソート n + k
1,000約 10,000約 1,100
100,000約 1,700,000約 100,100
1,000,000約 20,000,000約 1,000,100

n が増えるほど差が開く。比較ソートはどんなに工夫してもこの n log n が限界です。

グラフで見ると（横軸＝件数 n、縦軸＝手数）

緑（O(n+k)）はほぼ直線＝件数 n が2倍になれば手数も約2倍（線形）。
赤（O(n log n)）は上にそり返る曲線＝件数が増えると、1件あたりの手間（log n）も少しずつ増えるので、手数の伸びが直線より速くなる。
2本は左（データが少ない）ではほぼ重なっていますが、右に行く（データが増える）ほど差が開きます。値の範囲 k が小さいなら、件数が多い場面では分布数えソート（緑）が圧勝、というのがこのグラフの読み方です。

❓ Q&A: よくある質問

Q1. なぜ「比較しない」と速くなるの？

比較ベースのソートでは、n 個の要素を並べ替えるのに最低でも n log n 回の比較が必要であることが数学的に証明されています（決定木の下限）。分布数えソートは「数える」だけで順序を決めるため、この下限を回避でき、O(n + k) という線形時間が実現します。

Q2. では分布数えソートが万能なの？

いいえ。2つの大きな制約があります:

  • 整数（または整数に変換できる値）しか扱えない — 度数配列のインデックスとして使う必要があるため。
  • 値の範囲 k が大きいとメモリと時間を浪費する — 例えば k = 10億なら 10億個の配列を作る必要があり、現実的でない。

Q3. 具体的にどんなときに使う？

値の範囲が狭く、要素数が多い場面で威力を発揮します。例:

  • テストの点数（0〜100点）を10万人分ソート
  • 年齢（0〜120歳）を国民全員分ソート
  • RGB値（0〜255）でピクセルをソート（画像処理）

↑ 上の図のキャプションをかみ砕くと

まず言葉の確認です。

  • マス＝「値ごとの置き場所」。値0用のマス、値1用のマス…と並んでいる。
  • マスの数 ＝ 値の種類 ＝ k。点数（0〜100）なら 101個のマス。
  • n＝並べたいデータの件数（人数など）。

分布数えソートのやることは、たった2つです。

  1. ① 配る：データを1件ずつ「その値のマス」に入れる。大小を比べないので1件はほぼ一瞬（手間1）。n件あっても n回で終わる → O(n)。
  2. ② 回収する：マスを0番から順に取り出して並べる。マスの数 k だけ手間がかかる → O(k)。

合わせて O(n + k)。ここで k（マスの数）が n より小さければ、ほぼ O(n) の一直線で終わります。
逆に言うと、「マス＝値の種類が少なくて、データ件数が多い」ほど、配る作業（O(n)）が主役になり、比較ソートの O(n log n) よりずっと速くなる、というのが図の言いたいことです。

1.2 分布数えソートの3ステップ

10点満点の小テストの答案を、点数順に並べる作業を想像してください（下の図の入力 [4, 2, 2, 8, 3, 3, 1] は7人ぶんの点数です）。 まず点数ごとに山を作り（度数を数える）、次に「3点以下は何人？」と下の点数から人数を足していき（累積度数）、最後にその人数を手がかりに答案を点数順へ置いていきます（配置）。

補足: なぜ「累積度数」をわざわざ計算するの？

度数（count）を数えると「値3は2個ある」ことは分かります。でも、その2個を出力配列の何番目に書けばいいかまでは、度数だけでは分かりません。そこで累積度数の出番です。

累積度数は「自分以下の値が、全部で何個あるか」を表します。
たとえば「値3以下は5個」と分かれば、値3より小さい数で output の前のほうが5個ぶん埋まり、値3はちょうど5個目まで（= output[3], output[4]）に収まると、置き場所が計算だけで一発で決まります。比較は一切いりません。

配列役割教えてくれること
度数 count数える各値が何個あるか
累積度数 cumulative位置を決める各値をどこに置くか

ひとことで言うと: 度数＝「何個？」、累積度数＝「どこに置く？」。比較せずに置き場所を“計算”できるのが、累積度数のすごいところです。

1.3 なぜ末尾から処理するのか？

末尾から処理すると、同じ値の要素の元の順序が保たれます（安定ソート）。これは次回（第11回）で詳しく学びます。

例題 1

リスト内の各値の出現回数を数える

Python
def count_occurrences(data):
    max_val = max(data)
    count = [0] * (max_val + 1)  # 度数配列を0で初期化

    for value in data:
        count[value] += 1  # 該当する値のカウントを増やす

    return count

data = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3]
frequency = count_occurrences(data)

print(f"入力データ: {data}")
print(f"度数配列:   {frequency}")
for i, cnt in enumerate(frequency):
    if cnt > 0:
        print(f"  値 {i}: {cnt} 回")

度数配列から累積度数配列を作る

Python
def build_cumulative(count):
    cumulative = count[:]  # 度数配列をコピー
    for i in range(1, len(cumulative)):
        cumulative[i] = cumulative[i] + cumulative[i - 1]
    return cumulative

data = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3]
max_val = max(data)
count = [0] * (max_val + 1)
for value in data:
    count[value] += 1

cumulative = build_cumulative(count)

print(f"度数配列: {count}")
print(f"累積度数: {cumulative}")
for i in range(len(cumulative)):
    if count[i] > 0:
        print(f"  値 {i} 以下の要素数: {cumulative[i]}")

例題 3

基本的な分布数えソート

Python
def counting_sort_basic(data):
    if len(data) <= 1:
        return data[:]

    max_val = max(data)

    # Step 1: 度数を数える
    count = [0] * (max_val + 1)
    for value in data:
        count[value] += 1

    # Step 2: 累積度数を計算する
    for i in range(1, len(count)):
        count[i] += count[i - 1]

    # Step 3: 出力配列に配置する（末尾から = 安定ソート）
    output = [0] * len(data)
    for i in range(len(data) - 1, -1, -1):
        value = data[i]
        position = count[value] - 1  # 配置位置（0始まり）
        output[position] = value
        count[value] -= 1

    return output

data = [4, 2, 2, 8, 3, 3, 1]
result = counting_sort_basic(data)
print(f"入力: {data}")
print(f"出力: {result}")  # → [1, 2, 2, 3, 3, 4, 8]

assert result == sorted(data)
print("検証OK: sorted() と同じ結果")

例題 5

分布数えソートと挿入ソートの速度比較

値の範囲が 0~100 のとき、分布数えソートは挿入ソートに比べて圧倒的に高速です。

Python
import time
import random

def counting_sort(data, max_val):
    # Step 1: 度数を数える
    count = [0] * (max_val + 1)
    for v in data:
        count[v] += 1

    # Step 2: 累積度数を計算する
    for i in range(1, len(count)):
        count[i] += count[i - 1]

    # Step 3: 出力配列に末尾から配置する（安定ソート）
    output = [0] * len(data)
    for i in range(len(data) - 1, -1, -1):
        value = data[i]
        position = count[value] - 1
        output[position] = value
        count[value] -= 1

    return output

def insertion_sort(data):
    arr = data[:]
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr

random.seed(42)
sizes = [1000, 5000, 10000]
max_val = 100

print(f"{'サイズ':>8} {'分布数え':>14} {'挿入ソート':>12} {'速度比':>8}")
for size in sizes:
    data = [random.randint(0, max_val) for _ in range(size)]

    # 分布数えソートの実行時間
    start = time.time()
    counting_sort(data, max_val)
    ct = time.time() - start

    # 挿入ソートの実行時間
    start = time.time()
    insertion_sort(data)
    it = time.time() - start

    if ct > 0:
        ratio = it / ct
    else:
        ratio = 0
    print(f"{size:>8} {ct:>13.4f}s {it:>11.4f}s {ratio:>7.1f}x")

    freq[d] += 1

例題 例題1 やってみよう 解答

data = [0, 0, 1, 1, 1, 2, 3] に変更して実行した場合:

入力データ: [0, 0, 1, 1, 1, 2, 3]
度数配列:   [2, 3, 1, 1]
  値 0: 2 回
  値 1: 3 回
  値 2: 1 回
  値 3: 1 回

度数配列の長さは「最大値 + 1」で決まる（インデックス 0 から max_val までを使うため）。元のデータでは最大値が 9 だったので長さ 10 だったが、最大値が 3 になると長さは 4 に縮む。値の範囲 k が分布数えソートの空間計算量を決める重要な要因であり、最大値が小さいほど省メモリで済む。

例題 例題2 やってみよう 解答

data = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3] に対する累積度数配列の最後の値:

度数配列: [0, 2, 1, 2, 1, 2, 1, 0, 0, 1]
累積度数: [0, 2, 3, 5, 6, 8, 9, 9, 9, 10]
累積度数の最後の値: 10
元のデータの要素数: 10

累積度数配列の最後の値は、元のデータの要素数と必ず一致する。これは「最大値以下の要素数 = 全要素数」だから当然の結果。累積度数 cumulative[i] は「値 i 以下の要素がいくつあるか」を表すため、分布数えソートでは各値の「正しい配置位置」を一意に決めるための鍵になる。

例題 例題3 やってみよう 解答

Step 3 のループを range(len(data) - 1, -1, -1)（末尾から）から range(len(data))（先頭から）に変えても、整数キーのみのデータでは並び順は同じになる:

入力: [4, 2, 2, 8, 3, 3, 1]
出力（末尾から）: [1, 2, 2, 3, 3, 4, 8]
出力（先頭から）: [1, 2, 2, 3, 3, 4, 8]

ただし、キーに付随する情報を持つレコード（例: 同じ点数の生徒が複数人）を並べると差が出る。末尾から処理すると同じキーの要素の元の順序が保たれる（安定ソート）。先頭から処理すると同じキーの順序が反転してしまい、安定ソートではなくなる。整数だけのデモでは違いに気付きにくいが、実用上は末尾から処理するのが正しい。

例題 例題4 やってみよう 解答

num_students = 1000 に変えて実行した結果例（random.seed(42) 固定）:

平均点: 50.6
最低点: 0
最高点: 100
中央値 (sorted_scores[499]): 51

0〜100 の一様乱数なので、平均値も中央値も理論値 50 付近に集まる。100人のとき（平均約47.9）よりも 1000人のほう（平均約50.6）が理論値に近づく（大数の法則）。平均と中央値が近い場合はデータが対称に分布している証拠で、逆に大きくズレるときは外れ値や偏った分布（例: 一部の極端な値）の存在を疑える。分布数えソートは O(n + k) なので、k=101（点数範囲）が固定なら n が10倍になっても処理時間はほぼ10倍で済む。

例題 例題5 やってみよう 解答

max_val = 1000000（100万）に変えて実行した場合の結果例:

    サイズ        分布数え      挿入ソート      速度比
     1000       0.0850s      0.0420s      0.5x
     5000       0.0890s      1.0500s     11.8x
    10000       0.0950s      4.2000s     44.2x

max_val=100 のときは分布数えソートが圧倒的に速かったが、max_val=1000000 にするとサイズ 1000 では挿入ソートのほうが速くなる逆転現象が起きる。理由は分布数えソートが O(n + k) であり、ここで k=1000001（100万+1 の度数配列を初期化・走査するコスト）が支配的になるため。分布数えソートが有効なのは「k が n と同程度かそれ以下」のときであり、値の範囲が大きすぎる場合は適さない。これが「整数限定」「範囲が狭い」という分布数えソートの前提条件の意味。
