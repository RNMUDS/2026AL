説明

1.1 通常の挿入ソート（復習）

読み方: insertion sort = インサーション・ソート（語源は英語の "insert"（挿入する）＋ "sort"（並べ替える））。日本語では「挿入ソート」と呼びます。

前回学んだ挿入ソートでは、ソート済み部分から挿入位置を線形探索（読み方: せんけいたんさく / linear search / リニア・サーチ）（1つずつ比較）で見つけていました。ソート済み部分が長くなると、比較回数が増えます（最悪 O(n) 回）。

概念
配列: [2, 5, 8, | 3, 7, 1]
                ↑ この3を挿入したい
→ 8と比較: 3 < 8 → 右にずらす
→ 5と比較: 3 < 5 → 右にずらす
→ 2と比較: 3 > 2 → ここに挿入!

1.2 二分挿入ソート（Binary Insertion Sort）

読み方: binary insertion sort = バイナリ・インサーション・ソート。「二分」は「にぶん」と読み、英語の "binary"（2進・2つに分ける）に対応します。「挿入位置を二分探索で求める挿入ソート」という意味です。

辞書で単語を引くとき、端から1ページずつめくりませんよね。真ん中を開いて、目的の単語が左半分か右半分か判断して、さらに半分に絞る。これが二分探索です。

アイデア: ソート済み部分はすでに整列しているので、二分探索で挿入位置を効率的に見つけられます。

  • 比較回数: O(n) → O(log n) に改善
  • ただし、要素をずらす操作は依然 O(n) なので、全体は O(n2) のまま

具体例: [2, 5, 8, 12, 15] に key=7 を挿入する場合

線形探索なら：15 と比較 → 12 と比較 → 8 と比較 → 5 と比較（4回）
二分探索なら：中央の 8 と比較 → 左半分の中央 5 と比較（2回）
→ ソート済み部分が長くなるほど、二分探索の節約効果が大きくなる

❓ Q&A: 二分挿入ソートはなぜ全体が O(n²) のまま？

二分探索で比較回数は O(n) → O(log n) に減らせます。しかし、配列の途中に要素を挿入するには、後ろの要素を1つずつずらす必要があります。このシフト操作は最悪 O(n) 回かかります。

各 i について「比較 O(log n) + シフト O(n)」を行い、それを n 回繰り返すので、
合計コスト = n × (O(log n) + O(n)) = O(n²)。遅い操作（シフト）が全体を支配します。

💡 まとめ: 配列ベースのソートは「ずらす」コストが避けられない。本当に高速にしたいなら、マージソートやクイックソート（次回以降）のような O(n log n) アルゴリズムが必要。

1.3 Python の bisect モジュール

読み方: bisect = バイセクト（語源は英語の "bi-"（2つに）＋ "-sect"（切る）= 「二分する」）。insort＝インソート（insert + sort）。Python 標準ライブラリで、二分探索を C 言語実装で高速に提供します。

関数説明
bisect.bisect_left(a, x, lo, hi)ソート済みリスト a で、x を挿入すべき左端の位置を返す
bisect.bisect_right(a, x, lo, hi)同上、ただし右端の位置を返す
bisect.insort_left(a, x)x をソート済みリスト a に挿入する

⚠️ 注意: bisect はソート済みリストが前提。ソートされていないリストに対しては正しい結果を返しません。

1.4 バブルソート（Bubble Sort）

読み方: bubble sort = バブル・ソート（"bubble" = 泡）。日本語でもそのまま「バブルソート」と呼びます。隣接比較交換型（adjacent compare & swap）の代表例です。

水中の泡が上に浮かぶように、小さい値が配列の先頭に「浮かび上がる」ことからこの名前がつきました。隣同士を比較して交換を繰り返します。

最適化（早期終了 / early termination）: あるパスで1回も交換が起きなければ、すでにソート済みなので終了できます。これにより最良ケース（ソート済み）は O(n) になります。

1.5 シェルソート（Shell Sort）

読み方: Shell sort = シェル・ソート。考案者の Donald Shell 氏（1959年）の名前に由来します。「貝殻」ではないので注意。

挿入ソートの改良版で、離れた要素同士を先に比較・交換し、間隔（gap）を徐々に縮めていきます。間隔が1になったとき通常の挿入ソートになりますが、その時点でほぼ整列済みなので高速に動作します。平均計算量は O(n1.25) 程度（gap 列の取り方による）と、挿入ソートの O(n2) より速い。

書類の山を整理するとき、最初は大雑把に「100枚先のものと交換」して大まかに揃え、徐々に細かく「10枚先 → 1枚先」と精度を上げる ── これが gap を縮めていく感覚です。

用語（読み方）説明
bisect（バイセクト）Python 標準ライブラリ。ソート済みリストに対する二分探索・挿入位置の特定を C 言語実装で高速に行う。
bisect_left / bisect_right同じ値があるとき、左端を返すか右端の次を返すかの違い。差を取ると「同じ値の個数」になる。
insort（インソート）insert + sort の造語。ソートを保ったまま新しい値を挿入する。
二分挿入ソート（バイナリ・インサーション・ソート）挿入位置を二分探索で求める挿入ソート。比較は O(log n) になるが、シフト操作が O(n) のため全体は O(n2)。
バブルソート（バブル・ソート）隣接する2つの要素を比較・交換し、小さい値を先頭に「浮かび上がらせる」ソート。単純だが O(n2) と遅い。
早期終了（そうきしゅうりょう / early termination）あるパスで1回も交換が起きなければ、すでにソート済みなのでループを打ち切る最適化。最良ケースは O(n)。
比較回数（ひかくかいすう / comparison count）ソート中に「AとBはどちらが大きい？」と比較した合計回数。アルゴリズムの効率を測る指標。
交換回数（こうかんかいすう / swap count）2つの要素の位置を入れ替えた回数。比較とは別に、データ移動コストの指標。
例題 1

bisect で挿入位置を見つける

Python
import bisect

sorted_list = [10, 20, 30, 40, 50]
target = 25
position = bisect.bisect_left(sorted_list, target)
print(f"{target} の挿入位置: {position}")  # → 2

# 重複がある場合の left と right の違い
list_with_dup = [10, 20, 30, 30, 30, 40, 50]
left_pos  = bisect.bisect_left(list_with_dup, 30)   # → 2
right_pos = bisect.bisect_right(list_with_dup, 30)  # → 5

# insort_left で実際に挿入
demo = [10, 20, 30, 40, 50]
bisect.insort_left(demo, 25)
print(f"挿入後: {demo}")  # → [10, 20, 25, 30, 40, 50]

例題 2

二分挿入ソートの実装

Python
import bisect

def binary_insertion_sort(data):
    n = len(data)
    for i in range(1, n):
        key = data[i]
        position = bisect.bisect_left(data, key, 0, i)
        print(f"  Step{i}: key={key} → 挿入位置={position}")
        for j in range(i, position, -1):
            data[j] = data[j - 1]
        data[position] = key
        print(f"         結果: {data}")
    return data

test = [38, 27, 43, 3, 9, 82, 10]
binary_insertion_sort(test[:])

バブルソートの基本

Python
def bubble_sort(data):
    n = len(data)
    comparison_count = 0
    swap_count = 0

    for i in range(n):
        swapped = False
        for j in range(n - 1, i, -1):
            comparison_count += 1
            if data[j - 1] > data[j]:
                temp = data[j - 1]
                data[j - 1] = data[j]
                data[j] = temp
                swap_count += 1
                swapped = True
        print(f"  パス{i+1}: {data}")
        if not swapped:
            print("  交換なし → ソート完了!")
            break

    print(f"比較回数: {comparison_count}, 交換回数: {swap_count}")

bubble_sort([5, 3, 8, 1, 2])

例題 4

挿入ソートとバブルソートの比較

同じランダムデータに対して、挿入ソートとバブルソートの比較回数・実行時間を測定して比較します。

Python
import time, random

def insertion_sort_count(data):
    comparisons = 0
    n = len(data)
    for i in range(1, n):
        key = data[i]
        j = i - 1
        while j >= 0:
            comparisons += 1
            if data[j] > key:
                data[j + 1] = data[j]
                j -= 1
            else:
                break
        data[j + 1] = key
    return comparisons

def bubble_sort_count(data):
    comparisons = 0
    n = len(data)
    for i in range(n):
        swapped = False
        for j in range(n - 1, i, -1):
            comparisons += 1
            if data[j - 1] > data[j]:
                data[j - 1], data[j] = data[j], data[j - 1]
                swapped = True
        if not swapped:
            break
    return comparisons

data_size = 2000
test_data = [random.randint(0, 10000) for _ in range(data_size)]

start = time.time()
ins_comps = insertion_sort_count(test_data[:])
ins_time = time.time() - start

start = time.time()
bub_comps = bubble_sort_count(test_data[:])
bub_time = time.time() - start

print(f"挿入ソート:  比較{ins_comps}回, {ins_time:.4f}秒")
print(f"バブルソート: 比較{bub_comps}回, {bub_time:.4f}秒")

説明に必ず入れたいポイント（カンペにせず、確認用に）

ソート説明でおさえる点
二分挿入ソート 挿入位置を二分探索で探す挿入ソート／比較は O(log n) に減る／でもずらし（シフト）が O(n) なので全体は O(n²) のまま／たとえ（辞書を真ん中から引く）

バブルソートコードのトレース

以下のコードを実行せずに、各パスで data がどう変化するかを追い、最終出力を予測しなさい。
予測を書いた後に、AL09-3.py として保存・実行して確かめなさい。

Python ── AL09-3.py
data = [6, 3, 8, 1, 5]
swaps = 0
pass_num = 0

for i in range(len(data) - 1):
    swapped = False
    for j in range(len(data) - 1 - i):
        if data[j] > data[j + 1]:
            data[j], data[j + 1] = data[j + 1], data[j]
            swaps += 1
            swapped = True
    pass_num += 1
    print(f"パス{pass_num}: {data}")
    if not swapped:
        print("交換なし → 早期終了")
        break

print(f"総交換回数: {swaps}, パス数: {pass_num}")

ヒント: 各パスで隣接要素を比較し、左が大きければ交換します。パスごとに末尾から順に確定していくことに注目。早期終了条件にも注意。

解答例

例題 例題1 やってみよう 解答

list_with_dup = [10, 20, 30, 30, 30, 40] に対して実行した結果:

bisect.bisect_left(list_with_dup, 30)  → 2
bisect.bisect_right(list_with_dup, 30) → 5

bisect_left は 同じ値が並んでいる範囲の左端（一番最初の 30 の位置 = インデックス 2）を返し、bisect_right は 右端の直後（最後の 30 の次 = インデックス 5）を返す。つまり right - left = 3 が 30 の出現回数と一致する。重複を保ったまま挿入するなら insort_right、既存値の前に入れたいなら insort_left を使い分ける。

例題 例題2 やってみよう 解答

入力を [1, 2, 3, 4, 5]（ソート済み）に変えて実行した結果:

Step1: key=2 → 挿入位置=1
         結果: [1, 2, 3, 4, 5]
Step2: key=3 → 挿入位置=2
         結果: [1, 2, 3, 4, 5]
Step3: key=4 → 挿入位置=3
         結果: [1, 2, 3, 4, 5]
Step4: key=5 → 挿入位置=4
         結果: [1, 2, 3, 4, 5]

ソート済みデータでは、各ステップで挿入位置が 常に現在位置 i と一致する（key は data[0..i-1] のどの値よりも大きいため、bisect_left は範囲の右端 i を返す）。挿入位置が i なら要素のシフトが発生しないため、内側のループは1回も回らない。これが二分挿入ソートがソート済みデータで O(n log n)（比較のみ）になる理由。ただし通常の挿入ソート（線形比較）ならソート済みデータで O(n) になることに注意。

例題 例題3 やってみよう 解答

入力を [1, 2, 3, 4, 5]（ソート済み）に変えて実行した結果:

  パス1: [1, 2, 3, 4, 5]
  交換なし → ソート完了!
比較回数: 4, 交換回数: 0

1回目のパスで 1回も交換が起きない（swapped が False のまま）ため、早期終了フラグが発動して break でループを抜ける。比較は n-1 = 4回 だけ実行され、交換は 0回。これがバブルソートの最良ケース O(n)。早期終了フラグがない素朴なバブルソートだと、ソート済みでも O(n²) 回比較してしまうので、この最適化は重要。

例題 例題4 やってみよう 解答

data_size を 5000 に変えた場合の結果例:

data_size = 2000:
  挿入ソート:  比較 約 100万回,  約 0.10 秒
  バブルソート: 比較 約 200万回,  約 0.25 秒

data_size = 5000:
  挿入ソート:  比較 約 625万回,  約 0.65 秒
  バブルソート: 比較 約 1250万回, 約 1.60 秒

データ数を 2000 → 5000（2.5倍）に増やすと、比較回数は 約 2.5² = 6.25倍に増える。これは O(n²) の特徴。実行時間もほぼ同じ比率で増加する。両アルゴリズムとも比較回数のオーダーは同じだが、挿入ソートは else: break による早期打ち切りがあるため、バブルソートより比較回数が約半分になりやすい。

例題 例題5 やってみよう 解答

3パターン（n=2000）で insertion_sort_count と bubble_sort_count を実行した結果例:

パターン            挿入ソート比較   バブルソート比較
ランダム            約 100万回       約 200万回
ほぼ整列済み        約 4千回         約 200万回
逆順                約 200万回       約 200万回

差が最も大きいのは 「ほぼ整列済み」パターン。挿入ソートは data[j] > key が早めに偽になり break で内側ループを抜けられるため、比較回数が O(n) に近づく。一方、バブルソートは先頭に紛れた大きな値（turtle）が1パスにつき1マスしか右へ進めないため、早期終了フラグがあってもその値が定位置に着くまで約 n 回のパスが必要になり、O(n²) のまま。「ほぼ整列済み」データでは挿入ソートが圧倒的に有利になるのは、現実のデータ（追加更新でほぼ並んでいる）に強いという、挿入ソートの実用的な長所そのもの。逆順は両方の最悪ケースで、比較回数も実行時間もほぼ同じになる。
