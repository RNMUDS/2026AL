説明

1.1 なぜ挿入ソートが重要なのか

今回学ぶ挿入ソート（Insertion Sort）は、数あるソートアルゴリズムの中で「最初に学ぶべきソート」と言われ、しかも現代のプログラミング言語の内部で今も実際に使われている現役のアルゴリズムです。重要な理由は次の4つです。

挿入ソートが重要な4つの理由

  • ① 直感とコードが1対1で対応する ── 人間がトランプの手札を並べるときに自然にやる動きそのもの。「頭の中の手順をコードに翻訳する」練習の入口として最適
  • ② 「ほぼ並んでいる」データには最速クラス ── ほとんど整列済みのデータなら O(n) で動く。実際、Python の sort()（Timsort）など多くの言語の標準ソートは、内部の小さな区間の処理に今も挿入ソートを使っている
  • ③ 「同点」の順番が崩れない（安定ソート） ── 例: 出席番号順の成績表を点数順に並べ替えたとき、同じ70点の田中さん（出席番号3）と佐藤さん（出席番号8）は、ソート後も田中→佐藤の順のままになる。この「同じ値どうしは元の順序を保つ」性質を安定（stable）と呼び、挿入ソートはその代表例。「名前順に並べてから点数順にソートすると、同点の人は名前順に並ぶ」という実務でよく使うテクニックは、この性質があって初めて成り立つ（くわしくは 1.5 の Q4）
  • ④ 計算量を初めて「体感」できる ── 同じコードでもデータの並び方しだいで速さが100倍以上変わる（O(n) ⇔ O(n²)）。「計算量はデータに依存する」というアルゴリズム論の核心を、数字で確かめられる教材

前提として、「ソート（並べ替え）」そのものがなぜ重要かも確認しておきましょう。ソートとは、データを決まった順序（小さい順・大きい順・五十音順・日付順など）に並べ替えることです。スマホの連絡先（五十音順）、LINEのトーク一覧（新着順）、通販サイトの「安い順」、ゲームのランキング ── あなたが毎日見ている画面のほとんどは、裏でソートが動いた結果です。これほど使われる理由は「並んでいるデータは、その後のあらゆる処理が圧倒的に楽になる」からです。

ソートの効果ソートされていないと…ソート済みなら…
検索の高速化100万件の名簿から1人を探すのに、先頭から1件ずつ最大100万回確認二分探索（第4回）が使えて約20回で見つかる ── O(n) が O(log n) になる
データ分析100人のテストの中央値を出すには全員分を何度も見比べる並べて50番目を見るだけ。最高点・最低点も両端を見るだけ
重複の検出名簿に同じ人が2回いないか、全ペア約5000通りを比較隣どうしを99回見るだけ ── 同じ値は必ず隣に並ぶから
表示の整理バラバラの順で表示され、目で探すしかない名前順・日付順・点数順で一目で見つかる

つまりソートは「それ自体が目的」というより、検索・分析・整理を速くするための土台。その土台の作り方には挿入・選択・バブル・クイック・マージなど多くの方式があり、その中で人間の感覚にいちばん近いのが、今回の挿入ソートです。

この回で具体的に考えること（4つの問い）

  • 「正しい位置」はどう決まる？ ── どの要素と比較して、いつ止まるか（while の条件と break）
  • 比較とずらしは何回起きる？ ── 操作の回数を数える「計算量の目」を持つ
  • データの並び方で回数はどう変わる？ ── ソート済み・逆順・ランダムで実験して比べる
  • 同じ値が2つあったらどちらが先？ ── 安定ソートの意味を確かめる（発展課題につながる）

この4つは、以降のシミュレーター・例題・課題のすべてがこの順で答えていく問いです。迷子になったらここに戻ってください。

日常生活でどう生きるか: 挿入ソートの考え方は「すでに並んでいる列に、新しいものを追加する」場面でそのまま使えます。
  • 本棚に新しい本を1冊入れる ── 全部並べ直さず、正しい場所を探して1冊分ずらして差し込む
  • 提出されたプリントを学籍番号順に揃える ── 1枚取っては、整った束の正しい位置へ差し込む（枚数が少なければ人間にはこれが最速）
  • 予定表に新しい予定を入れる ── 時刻順に並んだ予定の間の正しい位置に挿入する
  • ゲームのハイスコアランキングに新記録を追加 ── 既存の順位を1つずつ下にずらして自分のスコアを入れる ── これはプログラムでも実際に挿入ソートの1パスそのもの
共通点は「大部分はすでに整っていて、少しだけ追加・修正する」こと。この状況では挿入ソートが理論上も実用上も最良に近い選択になります。逆に、完全にバラバラの大量データを一からソートするなら別の方式（第10回で学ぶ度数分布法など）が有利になることもあります ── 「状況によって最適な道具を選ぶ」のがアルゴリズムを学ぶ意味です。

1.2 挿入ソートの考え方

トランプのカードを手に持って、1枚ずつ正しい位置に差し込む動作と同じです。 最初のカードは「整列済み」（1枚だけなので）。 2枚目を取り、手札の中で正しい位置を見つけて差し込む。3枚目以降も同様。
🖱 トランプ手札ゲーム ── カードを引いて、自分で「すき間」をクリックして差し込もう
表向き = 手札（整列済み・小さい順）　緑の裏面 = 山札（まだ引いていない）　破線のすき間をクリックで差し込み

1.3 アルゴリズムの手順

1.2のカードゲームであなたの手がやっていたことを、プログラムの手順に分解すると 「① key を取り出す → ② 左隣と比較 → ③ 大きければ右へずらす → ④ 穴に挿入」 の繰り返しになります。下のシミュレーターをボタンで進めると、いまどの操作を実行中かが上のバッジで光ります。カードゲームの「手に持つ」が ①、「すき間をクリック」が ④ に対応します。

1.4 計算量

ケース比較回数特徴
最良（ソート済み）O(n)各要素で1回の比較のみ
平均O(n2)約 n(n-1)/4 回
最悪（逆順）O(n2)n(n-1)/2 回

1.5 よくある疑問 Q&A

Q1. key（読み: キー）って何ですか？

「いま手に取った1枚のカード」を表す一時変数（temporary variable / テンポラリ変数）です。key = data[i] でリストから値を取り出し、左側の整列済み部分の正しい位置に挿入します。具体例: data = [25, 34, 64, 12, 22] で i = 3 のとき key = 12。これを [25, 34, 64] の先頭に挿入する。

Q2. なぜ data[j + 1] = data[j] でずらすの？「交換」じゃダメ？

挿入ソートは「交換（swap / スワップ）」ではなく「ずらす（shift / シフト）」を使います。key をいったん退避してあるので、上書き（overwrite / オーバーライト）でずらせばよく、毎回 temp 変数を作る必要がない。これによって動作が約2倍速くなる。
例: [25, 34, 64, _] に key=12 を挿入する場合、data[3]=data[2]=64, data[2]=data[1]=34, data[1]=data[0]=25, 最後に data[0]=key=12。

Q3. j + 1 で挿入するのはなぜ？ j ではないの？

while ループの最後に j -= 1 されているからです。ループを抜けた時点で j は挿入位置の1つ左（または -1）になっているので、実際の挿入位置は j + 1。
例: key=12 が先頭に入る場合、j は -1 まで減って while を抜けるので、挿入は data[-1 + 1] = data[0]。

Q4. 「安定ソート（stable sort / ステーブルソート）」って？

同じ値を持つ要素の元の順序が保たれるソートのことです。挿入ソートは data[j] > key（厳密に大きいとき）でしかずらさないので、同じ値の場合は元の順序のまま。
具体例: 学生 [("田中", 70), ("鈴木", 80), ("佐藤", 70)] を点数でソートしても、田中と佐藤の順序は元のまま [("田中", 70), ("佐藤", 70), ("鈴木", 80)] になる。

例題 2

挿入位置を見つけて要素を挿入する

🎯 演習の目的: 挿入は「① 入る場所を探す → ② ずらして入れる」の2段階でできている。この例題ではまず①の「探す」だけを切り出して練習する。ポイントは右端から左へ比較し、key 以下の値に出会った瞬間 break で打ち切ること ── この「むだな比較をしない」工夫が、ソート済みデータで挿入ソートが O(n) と速くなる理由（例題4で確認）につながる。

Python
def find_insert_position(sorted_part, new_value):
    # 右端から左に向かって比較
    position = len(sorted_part)
    last_index = len(sorted_part) - 1
    for i in range(last_index, -1, -1):
        if sorted_part[i] > new_value:
            position = i
        else:
            break
    return position

sorted_part = [12, 25, 34, 64]
new_value = 22
position = find_insert_position(sorted_part, new_value)
print(f"挿入位置: {position}")  # → 1（12の後）
# 要素をずらして挿入 → [12, 22, 25, 34, 64]

例題 3

挿入ソートの1パス

🎯 演習の目的: カード1枚分の挿入（=1パス）を、コードで通しで実行する。例題1の「退避」と例題2の「探す」がここで合体し、key を取り出す → data[j+1] = data[j] でずらす → 穴に挿入、という流れになる。完成形の挿入ソート（例題4）はこの1パスを for で繰り返しているだけなので、ここを理解すれば全体はもう理解できたも同然。「やってみよう」の target_index=4 では、左側がソート済みという前提が崩れると正しく動かないことも確かめる。

Python
def insert_one_pass(data, target_index):
    key = data[target_index]
    j = target_index - 1

    while j >= 0 and data[j] > key:
        data[j + 1] = data[j]  # 要素を右にずらす
        j = j - 1

    data[j + 1] = key  # keyを空いた位置に挿入
    return data

data = [25, 34, 64, 12, 22]  # 先頭3つがソート済み
target_index = 3  # data[3]=12 を挿入する
result = insert_one_pass(data, target_index)
print(f"結果: {result}")  # → [12, 25, 34, 64, 22]

例題 4

完全な挿入ソート（比較回数カウント付き）

🎯 演習の目的: 例題3の1パスを for i in range(1, n) で繰り返すと全体がソートされることを確認する。さらに比較回数・移動回数を数字で数えることで、「アルゴリズムの速さはデータの並び方で変わる」ことを体感する ── ソート済みなら比較 n−1 回（O(n)）、逆順なら n(n−1)/2 回（O(n²)）。1.4 の計算量の表を自分の実験で裏づけるのがこの例題のゴール。

Python
def insertion_sort(data):
    n = len(data)
    comparison_count = 0
    shift_count = 0

    for i in range(1, n):
        key = data[i]
        j = i - 1

        while j >= 0:
            comparison_count += 1
            if data[j] > key:
                data[j + 1] = data[j]
                shift_count += 1
                j -= 1
            else:
                break

        data[j + 1] = key
        print(f"  ステップ{i}: key={key} → {data}")

    print(f"比較回数: {comparison_count}, 移動回数: {shift_count}")
    return data

test_data = [64, 34, 25, 12, 22]
insertion_sort(test_data[:])

例題 5

テキストベースのソート可視化

🎯 演習の目的: 数字の列だけでは「ソートが進んでいる感じ」がつかみにくいので、棒グラフの形に変えて目で見る。左下がりの形（逆順=最悪ケース）が1パスごとに右上がりに直っていく様子を観察すると、挿入中の値（@）が毎回左端まで突き抜ける＝移動回数が最大になる理由が直感で分かる。あわせて、print で動きを見える化するデバッグ技術そのものも、今後どのアルゴリズムでも使える道具として身につける。

棒グラフ風のテキストで、挿入ソートの過程を可視化します。整列済み部分を #、挿入中を @、未整列を - で表示します。

Python
def visualize_sort(data):
    n = len(data)
    max_value = max(data)

    for i in range(1, n):
        key = data[i]
        j = i - 1
        while j >= 0 and data[j] > key:
            data[j + 1] = data[j]
            j -= 1
        data[j + 1] = key

        # 棒グラフ風に表示
        for k in range(n):
            bar_len = int(data[k] / max_value * 30)
            if k == j + 1:
                bar = "@" * bar_len
            elif k <= i:
                bar = "#" * bar_len
            else:
                bar = "-" * bar_len
            print(f"  data[{k:>2}]={data[k]:>3} |{bar}")
        print()

visualize_sort([64, 34, 25, 12, 22, 50, 15])

標準課題 2

挿入ソートコードのトレース

以下のコードを実行せずに、各パスで data がどう変化するかを追い、最終出力を予測しなさい。
予測を書いた後に、AL08-3.py として保存・実行して確かめなさい。

Python ── AL08-3.py
data = [5, 2, 8, 1, 4]
comparisons = 0

for i in range(1, len(data)):
    key = data[i]
    j = i - 1
    while j >= 0 and data[j] > key:
        data[j + 1] = data[j]
        j -= 1
        comparisons += 1
    data[j + 1] = key
    print(f"パス{i}: key={key} → {data}")

print(f"比較回数: {comparisons}")

ヒント: 各パスで key（挿入する値）がどこまで左に移動するかを追います。while 条件の「data[j] > key」が偽になる位置が挿入先です。

解答例

例題 例題1 やってみよう 解答

例えば value_a = 100, value_b = 7 に変えて実行した場合:

交換前: a=100, b=7
交換後: a=7, b=100

方法1（一時変数 temp を使う方法）は、多くの言語で共通の交換手順。temp を介して値を保存しないと、value_a = value_b の時点で元の value_a が上書きされて失われてしまう。方法2（value_x, value_y = value_y, value_x）は Python のタプルの同時代入機能を使った書き方で、内部的には右辺を一度タプル (value_y, value_x) として評価してから左辺に展開するため、一時変数が不要になる。挿入ソートでは「整列済み部分の要素を右にずらす」場面で何度も値の入れ替えが発生するので、この交換操作が基礎になる。

例題 例題2 やってみよう 解答

sorted_part = [12, 25, 34, 64] で new_value = 50 を探した結果:

i=3: sorted_part[3]=64 > 50 → position = 3
i=2: sorted_part[2]=34 > 50 ではない → break
挿入位置: 3
挿入後: [12, 25, 34, 50, 64]

22 のときは position = 1（先頭付近）だったが、50 は34 と 64 のあいだに入るため position = 3 になる。このコードのポイントは「右から左へ」比較していることと、new_value 以下の値に出会った瞬間に break で打ち切る点。これにより、挿入ソートの内側ループ（while ループでの要素のずらし）と同じ「不要な比較を打ち切る」最適化を実現している。

例題 例題3 やってみよう 解答

data = [25, 34, 64, 12, 22] で target_index = 4 に変えた場合:

key = data[4] = 22
j = 3
while 判定: data[3]=12 > 22 ではない → ループに入らない
data[4] = 22  (そのまま)
結果: [25, 34, 64, 12, 22]

このコードは「data[0..target_index-1] がすでにソート済みである」ことを前提にしている。target_index = 3 のとき data[0..2] = [25, 34, 64] はソート済みなので正しく動くが、target_index = 4 では data[0..3] = [25, 34, 64, 12] がソートされていないため、結果も正しいソート結果にはならない。これが「挿入ソートの 1 パス」を抜き出した形であり、全体を完全にソートするには i = 1 から n-1 まで順に挿入を繰り返す必要がある（これが例題4の insertion_sort の構造）。

例題 例題4 やってみよう 解答

test_data = [1, 2, 3, 4, 5]（最初からソート済み）に変えた場合:

  ステップ1: key=2 → [1, 2, 3, 4, 5]
  ステップ2: key=3 → [1, 2, 3, 4, 5]
  ステップ3: key=4 → [1, 2, 3, 4, 5]
  ステップ4: key=5 → [1, 2, 3, 4, 5]
比較回数: 4, 移動回数: 0

各ステップで data[j] > key が一度で偽になり、すぐに break で while ループを抜ける。比較は1回だけ、移動は0回。n = 5 なら比較回数は n - 1 = 4 回。これが挿入ソートの最良ケース O(n) である。元のデータ [64, 34, 25, 12, 22] では比較回数が増えていたはず（最悪ケースに近いほど O(n²) に近づく）。「ほぼソート済みのデータには挿入ソートが速い」と言われる理由がここにある。

例題 例題5 やってみよう 解答

[7, 6, 5, 4, 3, 2, 1]（逆順）に変えて実行した場合、各パスで key（@）が毎回先頭まで移動する様子が観察できる:

パス i=1: key=6 を先頭に挿入 → [6, 7, 5, 4, 3, 2, 1]  (移動1回)
パス i=2: key=5 を先頭に挿入 → [5, 6, 7, 4, 3, 2, 1]  (移動2回)
パス i=3: key=4 を先頭に挿入 → [4, 5, 6, 7, 3, 2, 1]  (移動3回)
パス i=4: key=3 を先頭に挿入 → [3, 4, 5, 6, 7, 2, 1]  (移動4回)
パス i=5: key=2 を先頭に挿入 → [2, 3, 4, 5, 6, 7, 1]  (移動5回)
パス i=6: key=1 を先頭に挿入 → [1, 2, 3, 4, 5, 6, 7]  (移動6回)
合計移動回数: 1+2+3+4+5+6 = 21回

逆順データは挿入ソートの最悪ケースで、各 i パスで key が必ず先頭まで戻されるため、合計移動回数は 1 + 2 + ... + (n-1) = n(n-1)/2 になる。n = 7 なら 7 × 6 / 2 = 21 回。これが挿入ソートの計算量が O(n²) と言われる根拠。可視化すると @（挿入中の要素）が毎回 #（整列済み部分）の左端まで突き抜けていく動きが見て取れる。ソート済みデータ（例題4）と比較すると、データの「乱れ具合」によって性能が大きく変わることが体感できる。
